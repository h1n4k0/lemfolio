# Research Harness

The harness belongs to Lemfolio and does not import Keel or depend on model chat history. Its source index stores file/line provenance and graph edges for common LaTeX sections, definitions, claims, equations, labels, references, citations, bibliography entries and includes. BibTeX groups are balanced; comments and common verbatim environments are masked. Cross-file label references connect claims and equations. Graph edges are observed source links, not inferred proofs of logical dependence. Macro expansion, catcode changes, custom citation macros, conditional TeX and arbitrary source-generated structure require actual compilation or human interpretation.

Five workflows select domain prompts and acceptance criteria: chat, semantic edit, mathematical reasoning, literature and academic review. Context selection prioritizes an explicit source location and linked nodes, includes bounded source excerpts with original file hashes and line ranges, and hashes the resulting context snapshot. Source snippets remain untrusted research data. Review/chat return suggestions; editing modes can generate proposals for the store's independent approval transaction.

`coordinator.prepare_context` executes a finite domain preflight before model reasoning. Up to three explicit mathematical expression checks actually run the symbolic worker; literature/review modes query up to three explicit, intent or bibliography identifiers, and literature mode can run a bounded Crossref search when no identifier is available. Independent results, original metadata provenance, receipt hashes, source-checked prior evidence and compilation log tails enter the model context. It does not infer safe symbolic expressions from arbitrary LaTeX: when none were supplied, that missing validation is stated explicitly. Callers must filter stored receipts to the exact current project manifest revision.

`assess_verification` separates missing compilation, failed source/math/reference checks, uncertain metadata or unsupported expressions, and required human review. A compiler success is accepted as evidence only with a PDF hash in its receipt. A completed provider run is never research acceptance; even successful independent checks still require human scientific review. Symbolic equality is not proof, and identifier existence does not verify claim support.

Static verification checks duplicate and unresolved labels, unresolved citation keys, duplicate bibliography keys, missing included files and unbalanced environments. It explicitly reports compilation as not run and mathematical correctness as not verified. Both external `.bib` entries and classic `\\bibitem` sources are indexed.

The limited symbolic checker accepts Python-style arithmetic (`^` is normalized to exponentiation), named symbols, explicit boolean assumptions, and a small single-argument function whitelist. An AST whitelist constructs SymPy objects directly; neither Python `eval` nor SymPy string parsing is used. Subscripts, LaTeX syntax, arbitrary function calls, attributes, comprehensions and variable exponents are unsupported. Complexity, numeric intermediate sizes and subprocess duration are capped. Symbolic equivalence and sampled counterexamples are evidence classes, never a claim of mathematical proof; domains and singularities still require review. The official [SymPy parsing documentation](https://docs.sympy.org/latest/modules/parsing.html) warns that string-based parsing uses evaluation; this implementation avoids that route.

Metadata lookup accepts explicit DOI or arXiv identifiers only. Search uses Crossref bibliographic metadata. HTTP requests use fixed HTTPS Crossref/arXiv endpoints, disable redirects, enforce response/time limits, carry endpoint/time/body-hash provenance and never fetch arbitrary bibliography URLs. DOI responses must match the requested identifier; arXiv version requests must match the requested version. arXiv calls are spaced at least three seconds and successful lookups cache for one hour. A metadata match proves registry identifier existence only; it does not establish claim support, research quality, peer review or scientific correctness.

Primary protocol references: [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) and [arXiv API manual](https://info.arxiv.org/help/api/user-manual.html).
