# Lemfolio protocol and module contracts

Authoritative wire source: `contracts/v1/schema.json`, protocol **1.0.0**. Generate Python Pydantic/TypeScript DTOs with `scripts/generate_contracts.py`, static browser validators with `scripts/generate_validators.mjs`, and actual OpenAPI with `scripts/generate_openapi.py`. `scripts/check.ps1` checks drift. Do not hand-edit generated files or relax validation to obtain PASS.

- Web: React + TypeScript; Desktop: Rust + GPUI. Research Core, Harness, Indexer, Context, SymPy, Literature, Coordinator, Evidence Store, Runtime and Docker Compiler remain Python. Diff reuses Keel Rust. Keel Runtime remains unavailable until independently validated.
- `Store.capture_project(id)` derives bytes/text/raw hashes/content revision/main/generation/state_revision/snapshot_id from one managed lock/SQL transaction. Consumers reuse those bytes. Arbitrary external same-user multi-file mutation is outside this managed atomicity guarantee.
- `revision` remains the file-manifest hash. `state_revision` also binds main entry and monotonic generation, rejecting managed ABA and entry-switch approvals. Proposals bind digest and state; mutation uses content CAS. History restores entry by unique commit/state identity.
- Context coverage binds raw SHA and completeness to character/original UTF-8 byte ranges, dependencies and omissions. Character and whole-JSON budgets are separate; full task admission checks 1 MB before prepared evidence is published.
- Agent result: `answer`, `changes`, `checks`. A change chooses full `content` or guarded `edits`, unused field null. Existing full replacements require complete visibility. Nonempty unique `old_text` anchors must lie in visible coverage; API rebuilds frozen full source and rejects overlap. Explicit manual `content:null` can propose deletion; absence of an operation cannot.
- Runtime queued state/event and terminal result/event/state commit atomically. CLI status/execution share a subscription-only child environment with updates disabled. Windows 10+ CLI trees are assigned to a non-inheritable kill-on-owner-exit Job during process creation; unsupported ownership fails closed. API fallback is explicit. Automatic/cross-provider execution recovery stays unsupported; legacy runs without a recorded guard retain unknown process-termination status.
- Store source application and scientific verification have separate durable outcomes. `DecisionResponse.apply_status` stays applied after post-commit verifier errors. A retry requires the same approved state and never reapplies source. Restart marks uncommitted pending verification failed, not complete.
- Compiler consumes the exact verification snapshot; identity binds project/snapshot/state/content/hashes/main/engine/image. Legacy receipts have null identity and remain history. New/failed/cancelled build selections clear previous PDF.
- Compiler admission bounds active jobs/queries, retention and conservative storage/free-space reservations. Existing Docker isolation/resource limits remain. SyncTeX uses named, bounded-output, persisted ownership/cleanup; unconfirmed cleanup blocks admission. Aggregate output polling is a soft limit, not a host hard quota.

See `docs/architecture.md` and the dated review for measured tests, semantics and limitations. Universal proof verification, public hosting and unvalidated Keel execution are not claimed complete.
